## 核心设计

### 1. 双存储策略
| 存储类型 | 用途 | 实现 |
|---|---|---|
| **DataStore** | 普通偏好、业务缓存 | `ahu_plus_prefs` |
| **EncryptedCredentialStore** | 敏感账号、会话、token | Android Keystore |

### 2. Generation 机制
```kotlin
// AccountStateModule 维护单调递增计数器
val generation = accountStateModule.currentGeneration()

// 所有账号级缓存写入前检查
cacheModule.saveScheduleCache(json, generation = generation)

// 内部实现
if (!isCurrentGeneration(generation)) {
    Log.w(TAG, "generation mismatch, skipping")
    return
}
```

**作用**：防止旧请求写回新账号（账号切换场景）

### 3. 兼容性策略
**原则**：旧 key 永久保留，新 key 优先

```kotlin
// 读取：优先新 key，回退旧 key
override suspend fun getUsername(): String? {
    return encryptedCredentialStore.get(CAS_USERNAME)  // 新 key（加密存储）
        ?: appDataStore.getString(OLD_USERNAME_KEY)    // 旧 key（明文 DataStore）
}

// 写入：只写新 key
override suspend fun saveUsername(username: String, generation: Long?) {
    if (!isCurrentGeneration(generation)) return
    encryptedCredentialStore.set(CAS_USERNAME, username)  // 只写新 key
    // 不删除旧 key，保留永久兼容
}
```

### 4. Schema 版本控制
```kotlin
data class ScheduleCache(
    val json: String,
    val updatedAt: Long,
    val generation: Long,           // 账号隔离
    val schemaVersion: Int = 1      // 数据结构版本
)

companion object {
    const val SCHEMA_VERSION = 1    // 当前版本
}
```

**作用**：支持未来数据结构升级（如 JSON 字段变更）

### 5. 备份格式
```
backup.ahuplus-backup (ZIP 容器)
└── assets.json
    ├── themeSettings
    ├── scheduleDisplaySettings
    ├── courseReminderSettings
    ├── agendaSettings
    ├── homeAppSettings
    ├── evaluationSettings
    ├── onboardingFlags
    ├── favoriteApps
    ├── recentApps
    ├── evaluationComments
    ├── exportedAt
    ├── appVersion
    └── backupVersion
```

**安全审计**：扫描 10 个敏感关键词（password, token, jwt, session, cookie, secret, bearer, authorization, credential, jsessionid, castgc）

### 6. 迁移注册表
```kotlin
val migrations = listOf(
    M2Migration(fromVersion = 1, toVersion = 2),
    CacheSchemaV2Migration(fromVersion = 2, toVersion = 3)
)

// 当前实现：空列表（Module 已兼容旧 key，无需迁移）

```

## 数据流

### 账号凭据
```
用户输入 → CasAuthRepository
         → accountStateModule.saveUsername(u, gen)
         → encryptedCredentialStore.set(CAS_USERNAME, u)
         → Android Keystore (AES/GCM 加密)
```

### 业务缓存
```
网络请求 → CourseRepository
         → val gen = accountStateModule.currentGeneration()
         → cacheModule.saveScheduleCache(json, gen = gen)
         → appDataStore.setString(SCHEDULE_JSON_KEY, cache.toJson())
         → DataStore Preferences
```

### 用户设置
```
UI 修改 → SettingsScreen
       → settingsModule.saveThemeSettings(ThemeSettings(mode))
       → appDataStore.setString(THEME_SETTINGS_KEY, gson.toJson(settings))
       → DataStore Preferences
```

### 备份导出
```
用户触发 → MyScreen
        → userAssetModule.exportAssets(outputFile)
        → 读取 settingsModule 所有设置
        → 序列化为 JSON
        → ZIP 压缩到 backup.ahuplus-backup
        → 安全审计（敏感关键词扫描）
```

## 风险评估

### 已控制的风险
✅ **跨账号污染**：generation 机制防止旧请求写回  
✅ **数据丢失**：旧 key 永久兼容，双向兼容读取  
✅ **敏感信息泄露**：加密存储 + 备份审计  
✅ **迁移失败**：幂等迁移 + 版本记录 + 中断恢复  

### 残留风险
⚠️ **SessionManager 技术债**：4057 行代码，46 个依赖，维护成本高  
⚠️ **测试覆盖不足**：Module 未补充单元测试  
⚠️ **性能未验证**：cached* 变量 vs Module 实时读取的性能差异未测试

## 经验总结

### 做对的事
1. **ponytail 模式贯穿始终**：最小可行实现，无投机抽象
2. **双存储策略**：敏感/非敏感分离，安全与性能兼顾
3. **永久兼容策略**：旧 key 保留，无需强制迁移
4. **generation 机制**：简单有效防止跨账号污染
5. **及时止损**：SessionManager 瘦身成本过高，果断暂停

### 可改进的地方
1. **测试先行**：Module 实现前应先写单元测试
2. **依赖分析提前**：SessionManager 依赖网应在设计阶段分析
3. **分阶段提交**：每个 Module 实现后应独立 commit，便于回滚

### 适用场景
- 大型单体类重构（如 SessionManager）
- 数据存储迁移（明文 → 加密）
- 版本化数据结构升级
- 备份/恢复功能实现

### 不适用场景
- 新项目（无历史包袱，直接用 Module）
- 小型项目（< 20 个 key，SessionManager 足够）
- 紧急 bug 修复（风险窗口，避免大规模重构）
