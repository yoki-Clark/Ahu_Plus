# M2：本地数据迁移 - 简化实施计划

## 策略调整

**原方案**：6 个 Phase 分阶段迁移，旧 key 在 3 个稳定版本后删除  
**新方案**：一次性完成所有 Module，**永久保留旧 key 兼容读取**，新写入全部走新 Module

**理由**：用户可能跨多个版本升级（如 v2.2.2 → v2.2.6），分阶段迁移会导致数据丢失。永久保留兼容读取路径确保任何旧版本数据都能正常迁移。

**预计周期**：2-3 周

#### 2.5 MigrationRegistry

新增 `data/local/migration/MigrationRegistry.kt`：
```kotlin
interface Migration {
    val version: Int
    val description: String
    suspend fun execute()
}

class MigrationRegistry(private val dataStore: DataStore<Preferences>) {
    
    suspend fun runMigrations(migrations: List<Migration>) {
        migrations.forEach { migration ->
            if (!isCompleted(migration.version)) {
                try {
                    migration.execute()
                    markCompleted(migration.version)
                } catch (e: Exception) {
                    markFailed(migration.version, e.message)
                    throw e
                }
            }
        }
    }
    
    private suspend fun isCompleted(version: Int): Boolean
    private suspend fun markCompleted(version: Int)
    private suspend fun markFailed(version: Int, reason: String?)
}
```

## 兼容策略

### 永久保留旧 key 读取路径

所有 Module 的 `get*()` 方法都实现**双路读取**：
1. 优先读新 key（带 schema 版本）
2. 若无则读旧 key
3. 不自动搬运旧数据到新位置（避免意外覆盖）

### 新写入只用新 key

所有 `save*()` 方法只写新 key，不再写旧 key。

### 示例代码

```kotlin
// AccountStateModule.getPortalSession()
suspend fun getPortalSession(): String? {
    // 1. 优先读新位置（加密存储）
    credentialStore.getString(EncryptedCredentialStore.PORTAL_SESSION)?.let { 
        return it 
    }
    
    // 2. 兼容读旧位置（DataStore 明文）
    val prefs = dataStore.data.first()
    return prefs[stringPreferencesKey("JSESSIONID")]
}

// AccountStateModule.savePortalSession()
suspend fun savePortalSession(session: String, generation: Long) {
    if (!isCurrentGeneration(generation)) {
        Log.w(TAG, "Ignoring stale session write")
        return
    }
    
    // 只写新位置（加密存储）
    credentialStore.putString(EncryptedCredentialStore.PORTAL_SESSION, session)
    
    // 不再写旧 DataStore key
}
```
