# M2：本地数据与用户资产迁移 - 实施计划

## 概览

本计划基于 `20-可持续运营改造计划.md` 的 M2 里程碑，将 `SessionManager`（4035 行）从"包含所有本地状态的浅 Module"重构为"兼容门面 + 账号生命周期协调者"。

**预计周期**：4 至 6 周（单人串行）  
**前置条件**：M0 已完成  
**可独立发布**：是，需分多个版本渐进迁移

## 当前基线

### 现有结构
- `SessionManager.kt`：4035 行，承载凭据、会话、设置、缓存、用户资产、迁移等所有职责
- `AppDataStore.kt`：统一 DataStore 入口，已支持课程备注、节次备注、考核方案
- `EncryptedCredentialStore.kt`：基于 Keystore 的凭据加密存储，已定义账号与第三方凭据 key 集合
- 46 个 Repository 直接或间接依赖 `SessionManager`

### 现有数据分类（混合存储）
| 类别 | 当前位置 | 问题 |
|---|---|---|
| 敏感凭据 | `EncryptedCredentialStore` + `SessionManager` 内存缓存 | 部分已迁移，SessionManager 仍持有 @Volatile 缓存 |
| 账号会话 | DataStore + 内存 | 账号 generation 机制存在但未深化 |
| 用户资产 | DataStore（课程/节次备注、考核方案） | 缺少导出、恢复和冲突策略 |
| 应用设置 | DataStore（主题、导航、提醒等） | 与业务缓存混在同一文件 |
| 业务缓存 | DataStore（JSON 字符串） | 缺少 schema 版本、账号归属、清理策略 |

## 目标架构

```
SessionManager (门面 + 协调器)
├── CredentialModule          // 敏感凭据
```

### Phase 5：迁移注册表与幂等性（1 周）

**目标**：版本化迁移，支持中断恢复

#### 5.1 MigrationRegistry 实现
新增 `data/local/migration/MigrationRegistry.kt`：
```kotlin
class MigrationRegistry(private val dataStore: DataStore<Preferences>) {
    
    suspend fun runMigrations(migrations: List<Migration>) {
        migrations.forEach { migration ->
            if (!isCompleted(migration.version)) {
                try {
                    migration.execute()
                    markCompleted(migration.version)
                } catch (e: Exception) {
                    markFailed(migration.version, e.message)
                    throw e
                }
            }
        }
    }
    
    private suspend fun isCompleted(version: Int): Boolean
    private suspend fun markCompleted(version: Int)
    private suspend fun markFailed(version: Int, reason: String?)
}

interface Migration {
    val version: Int
    val description: String
    suspend fun execute()
}
```
